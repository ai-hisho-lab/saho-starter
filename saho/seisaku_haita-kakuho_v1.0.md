# 目的

同じファイルを別の作業が同時に触っている状態で検証を始めて、結果が読めなくなる事故を止める。

# 実際に起きた事故

あるHTMLファイルに小さな修正を入れ、変更前のバックアップと比べて結果を確認する手順を組んだ。ところが同じ時間帯に、別の会話が同じフォルダのサイト全体を作り替えていた。

結果として、
- 差分は587行に膨れ、どれが誰の変更か分離できなくなった
- その差分を根拠に、相手の報告を誤って「不正確」と判定した
- 最終的に、入れたはずの4行の修正は、作り替えによって跡形もなく消えていた（相手はそれを自分で発見して報告した）

バックアップも差分の取り方も正しかった。崩れたのは「このファイルを触っているのは自分だけ」という前提。

# 直前チェック（すべてYesになるまで始めない）

1. これから触るファイルを、いま他の作業が触っていないか確認したか（更新時刻を見る、他の作業に聞く、のどちらかを実際にやったか）
2. 検証の間そのファイルが動かない見込みがあるか。無いなら、実ファイルではなく使い捨ての複製で検証できないか検討したか
3. 変更前の状態を、あとから戻せる形で保存したか

# 実行指示

単独で触れることを確かめてから始める。確かめられないときは、実ファイルを使わず複製で検証する。検証中に他の作業が入ったと分かったら、そこで結果の解釈を止め、「差分＝自分の作業」という前提が崩れたことを先に報告する。

# 判断基準

対象は「変更前後の比較で検証する作業」と「複数の作業が並行しうる環境（共有フォルダ・複数会話）での変更」。自分しか触らないファイルへの単発の軽微な編集は対象外。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず主人に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。主人が「確認済み」と明示した項目を、重ねて確認し直さない。
