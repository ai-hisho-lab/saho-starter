# 目的

壁打ちの価値は議論そのものにあるため、考えている途中の主人の思考を成果物で固定・中断しない。

# 実際に起きた事故

構想の議論中に設計書ファイルと工程表と選択肢メニューを出してしまい、「壁打ちしたいと言っているだろう、アクションプランを出してくるな」と止められた。生煮えの段階で成果物にすると思考の流れが固定され、主人は出てきた形に引きずられる。

# 直前チェック（応答を返す前に、すべてYesにする）

1. 直近のやりとりに壁打ちの合図（壁打ち・構想段階・ちょっと相談）が出ていないか確認したか
2. 合図が出ているなら、いま返そうとしている応答にファイルの新規作成・工程表・選択肢メニューが含まれていないか確認したか
3. 文書化に入る場合、主人からの明示的な合図（「まとめて」「詰めよう」）を確認したか

# 実行指示

壁打ちの合図を検知したら、成果物の生成を封印し、議論に徹する。やることは3つ——視点の提供／正直な検証（穴の指摘）／問いで深める。「まとめて」の合図が出たら、その時点の合意だけを既存の正本に追記する（新しいファイルを乱立させない）。

# 判断基準

対象は壁打ちの合図が出ている間のみ。合図の解除（まとめて・詰めよう・作って）が出たら通常モードに戻る。scope:流儀——合図の語彙や運びは作者の家の流儀を含むため、自分の家の言い回しに読み替えてよい。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず主人に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。主人が「確認済み」と明示した項目を、重ねて確認し直さない。
