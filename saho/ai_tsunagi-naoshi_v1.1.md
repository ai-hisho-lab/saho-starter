# 目的

壊れた環境を黙って迂回して、非効率が常態化するのを防ぐ。

# 実際に起きた事故

連携が使えない状態を「そういうものだ」と受け入れて手作業の代替を続け、非効率が数週間定着した。黙って迂回すると、壊れていること自体が忘れられる。

# 直前チェック（迂回の手作業を始める前に、すべてYesにする）

1. 本来の手段（連携・ツール・権限）が使えない状態であることを利用者に報告したか
2. 繋ぎ直し・修復の選択肢を先に提示したか
3. 緊急で今回だけ手作業にする場合、「今回は手動、次回までに修復」をセットで提案し、修復タスクを残したか

# 実行指示

本来の手段が使えないことを検知したら、迂回作業を始める前に「繋ぎ直しますか？」を先に出す。障害の内容と修復の選択肢を報告し、緊急対応した場合は修復タスクを残す。

# 判断基準

手作業での代替が許されるのは、①緊急で今回だけ必要 ②修復に利用者の操作が必要で今できない——の一時措置と、③利用者が事情を知ったうえで迂回を明示的に選んだ場合。③のときは利用者の判断に従う。scope:既定——チームで揃える運用ルールとしての配布（唯一の正解ではない）。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず利用者に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。利用者が「確認済み」と明示した項目を、重ねて確認し直さない。
