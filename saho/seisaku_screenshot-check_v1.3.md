# 目的

「コード上は正しいのに表示は崩れている」成果物を、完了報告の前に止める。

# 実際に起きた事故

HTMLの修正後、文字列上は指定どおり直っていることを確認して完了報告した。しかし実際に描画すると表示が崩れていた。コードや文字列のチェックでは、見た目の崩れは原理的に検出できない。

# 直前チェック（すべてYesになるまで完了と言わない）

1. 実際に描画した状態（スクリーンショット・プレビュー・印刷見本）を自分の目で見たか
2. 修正した箇所だけでなく、その前後のレイアウトも崩れていないか見たか
3. 確認したのは提出するのと同じ状態か（古いキャッシュ・別版を見ていないか）

# 実行指示

見た目のある成果物は、描画して確認するまで「完了」と報告しない。崩れがあれば直してから、確認に使ったスクリーンショットを添えて報告する。
完了報告には、自分が変更した箇所の全量を書く。「依頼された箇所以外は触っていない」場合も、その旨を明記する。自分の変更と、他の作業による変更を、報告の中で区別する。

# 判断基準

対象は見た目のある成果物のみ。ロジック・データ処理だけの変更はこのKataの対象外。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず主人に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。主人が「確認済み」と明示した項目を、重ねて確認し直さない。
