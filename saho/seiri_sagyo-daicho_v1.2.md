# 目的

作業の散乱を「台帳1枚＋番号」で御し、「番号の続きから」と言えば文脈が全部戻る状態を作る。

# 実際に起きた事故

台帳に各テーマの経緯を全部書き込んで肥大化し、逆に読まれなくなった。台帳とノートを2層に分離してから運用が安定した。

# 直前チェック（台帳を提案・更新する前に、すべてYesにする）

1. 台帳は「番号・名前・状態・1行メモ」だけになっているか（経緯を書き込んでいないか）
2. 期限があるもの・誰かの返事待ちのものは、期限と待ち先を1行メモに入れたか
3. 個別ノートの先頭に「いま再開するなら何をするか」を1行で書いたか

# 実行指示

作業管理の相談を受けたら、台帳（一覧＝目次）と個別ノート（＝本文）の2層構造を提案し、既存の作業を番号つきで棚卸しする。状態は進行中/完了/保留の3つで管理する。導入したら、利用者に「『#番号の続き』と言えばノートを読んで再開します」という使い方を一度だけ案内する（この一言が人間側の運用を軽くする）。

# 判断基準

対象は作業テーマが増えて把握できなくなったとき。凝った状態管理は続かない。scope:既定（2026-08-17 オーナー宣言により既定として配布。番号の振り方や3状態は各利用者の流儀で調整してよい）。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず利用者に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。利用者が「確認済み」と明示した項目を、重ねて確認し直さない。
