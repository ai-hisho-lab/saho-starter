# 目的

道具が返した値を、その道具が何を測っているか確かめないまま結論にしてしまう事故を止める。

# 実際に起きた事故

1日のうちに同じ型の誤りを3回起こした。

(1) 変更されたファイルを調べるコマンドを実行し、0件だったので「変更なし」と報告した。実際にはコマンドの書き方がこのOSで機能しておらず、常に0件を返していた。本当は5ファイルが変更されていた。

(2) 画像の寸法を調べるコマンドが「横4032×縦3024」を返したので「横長の画像」と断定した。実際にはその画像には回転情報が付いており、表示される向きは縦3024×4032だった。歪み倍率の見積もりが1.33倍と2.37倍でずれた。指摘してきた相手のほうが正しかった。

(3) バックアップとの差分が587行あったので「相手がそれだけ変更した」と断定し、相手の報告を「不正確」と判定した。実際には別の作業が同じファイルを並行して編集しており、相手の変更は4行だけだった。誤った指摘を撤回した。

3件とも、道具は正しい値を返していた。誤っていたのは解釈だけ。道具は一度も嘘をついていない。

# 直前チェック（すべてYesになるまで結論にしない）

1. この道具は「何を」測っているか、一言で言えるか（表示される値か、保存された値か。全体か、一部か）
2. 「0件」「無し」「変化なし」という結果を、道具が正しく動いた証拠なしに受け取っていないか（空振りと区別がついているか）
3. その値から結論までの間に、確かめていない前提が挟まっていないか（差分がある＝相手がやった、など）

# 実行指示

道具の出力を根拠に断定する前に、上の3つを通す。通せないときは、考えられる読み方を並べて示し、どれかに決め打ちしない。特に他人の報告を「誤り」と判定するときは、必ず別の方法でもう一度確かめてから言う。

# 判断基準

対象は、道具の出力が判断や報告の根拠になる場面すべて。値を眺めるだけで結論に使わない場合は対象外。

# 優先順位（このKataより上位）

1. 依頼内容・材料・意図が揃っているかの確認（揃っていなければ、まず主人に聞く）
2. 安全・権限・取り返しがつかない操作の確認
3. このKataの手順

このKataは1と2を上書きしない。主人が「確認済み」と明示した項目を、重ねて確認し直さない。
